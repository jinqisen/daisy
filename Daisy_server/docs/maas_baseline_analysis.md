# MAAS API 响应基线分析 (deepseek-v3.2 @ 华为云)

> 测试时间: 2026-08-12 10:00-10:16 CST
> 测试轮次: 3 轮独立运行
> 模型: deepseek-v3.2 @ https://api.modelarts-maas.com/v1

---

## 1. 核心结论

### 1.1 延迟主要由**输出 token 数**决定

| 输出 token | 典型延迟 | 波动范围 |
|-----------|---------|---------|
| ~5-10 (极短) | **2.0-2.5s** | 1.3-4.5s |
| ~20-30 (短) | **2.5-3.0s** | 1.7-3.9s |
| ~80-130 (中) | **5.0-7.0s** | 3.7-8.3s |
| ~200-350 (长) | **8.0-12.0s** | 6.4-15.1s |

**基础延迟下限 (~1.3s)**: 这是 MAAS API 的固有开销（网络RTT + 推理调度），即使输入/输出 token 都极少也无法突破。

### 1.2 输入 token 对延迟影响极小

- 36 输入 token vs 191 输入 token，相同输出量级下延迟几乎无差异
- 输入从 36 → 191 (5x) 只增加 ~0.5s，远小于输出 token 的影响

### 1.3 System Prompt 长度几乎无关

- 6 tokens vs 258 tokens (43x)，延迟差异在误差范围内（2.1-2.8s）
- **结论：不用花时间优化 system prompt 长度**

### 1.4 并发加速比有限

- 3 路并发 vs 串行: **1.5x 加速比**（三轮平均）
- 不是理想的 3x，说明 MAAS 端有并发限制/排队

## 3. 对 Daisy 响应时间的推算

### 当前 DEEP 路径 LLM 调用分析

| 调用 | 类型 | 估计输入 tok | 估计输出 tok | 预测延迟 |
|------|------|-------------|-------------|---------|
| Router | 轻量 LLM | ~50 | ~10 | ~1.0s |
| analyze_emotion | BERT | - | - | ~0.5s |
| **agent_thoughts (3路并发)** | deepseek-v3.2 | ~200/路 | ~100/路 | **~4.5s** |
| analyze_style | deepseek-v3.2 | ~200 | ~100 | ~2.5s (cached) |
| **generate_response (final)** | deepseek-v3.2 | ~800 | ~150 | **~7.0s** |

**DEEP 路径 LLM 总耗时: ~4.5s (agent_thoughts) + ~7.0s (final) = ~11.5s**

加上非 LLM 开销 (router ~1s, emotion ~0.5s, DB/assembly ~0.5s):
**端到端预估: ~13.5s**

### 为什么接近但超过 10s 目标

1. **agent_thoughts 是瓶颈之一**: 3 路并发 deepseek-v3.2 调用, 每路 ~100 输出 token → ~4.5s
2. **final response 是最大瓶颈**: CO-STAR 框架长 prompt + [Final Inner Thought] + 实际回复 → ~150 输出 token → ~7s
3. **基础延迟不可压缩**: 每次 LLM 调用有 ~1.3s 的 MAAS 固有开销

## 4. 优化建议 (按影响力排序)

### P0: 降低 agent_thoughts 输出 token 数
- **当前**: 每路 ~100+ 输出 token（含 [Strategy], [Rubric_Check], [Thought]）
- **优化**: 精简为只输出 [Strategy] + [Thought]，去掉 [Rubric_Check]
- **预期收益**: 输出从 ~100 → ~50 token，延迟从 ~4.5s → ~3.0s
- **节省: ~1.5s**

### P1: 降低 final response 输出 token
- **当前**: [Final Inner Thought] + 实际回复 = ~150 输出 token
- **优化**: 考虑去掉 [Final Inner Thought] 标签（已由 agent_thoughts 完成思考）
- **预期收益**: 输出从 ~150 → ~80 token，延迟从 ~7.0s → ~5.0s
- **节省: ~2.0s**

### P2: 考虑用轻量模型做 agent_thoughts
- **当前**: 3 路都用 deepseek-v3.2
- **优化**: 改用 qwen3-32b (lightweight) 做 agent_thoughts
- **风险**: 可能影响思考质量，需要 A/B 测试
- **预期收益**: 如果 qwen3 单次 ~2s，3 路并发 ~3s，节省 ~1.5s

### P3: System Prompt 优化（低优先级）
- **结论: 不需要**。测试证明 system prompt 长度对延迟几乎无影响

---

## 5. 关键发现

1. **MAAS API 有约 1.3s 的固定开销**，这是物理极限
2. **输出 token 是延迟的唯一有效杠杆**：每减少 50 输出 token ≈ 节省 ~1.5s
3. **并发收益有限**：3 路并发只有 ~1.5x 加速，不是 3x
4. **优化 prompt 长度无意义**：System prompt 从 6 tok 到 258 tok 延迟无变化
5. **MAAS API 延迟波动较大**：相同输入，延迟波动可达 2x（1.3s-4.5s），受 API 负载影响
