# CONSENSUS_Merge_OS: 多人格内心OS融合优化

## 1. 需求与目标
- **核心需求**: 解决多人格内心独白 (OS) 割裂、缺乏融合感的问题。
- **目标状态**: 系统在生成回复前，能够根据人格权重（如 70% A + 30% B）综合权衡各个人格的独立想法，形成一个具有复杂性、纠结感或层次感的“最终思维流”。
- **约束**: 
  - 保持低延迟（尽量不增加额外的串行 LLM 调用）。
  - 保持代码结构清晰。

## 2. 技术决策：Prompt-Guided Synthesis (方案 B+)
我们决定采用 **在最终生成阶段通过 Prompt 引导融合** 的方案，而不是引入独立的 LLM 节点。

### 理由
1.  **性能优先**: 当前项目正在进行响应速度优化 (`Optimization_Response_Time_v2`)，增加额外的串行 LLM 节点（需耗时 2-3秒）会破坏优化成果。
2.  **上下文完整性**: 最终回复模型（Final Generator）同时拥有画像、历史、风格指南。让它在生成回复的同一上下文中进行“思维融合”，能确保思维与行动的高度一致性。
3.  **CoT (思维链) 优势**: 让模型先输出 `[Synthesized Thought]` 再输出 `[Response]`，实际上是强制模型进行 Chain-of-Thought 推理，这本身就能提高回复质量。

## 3. 验收标准
1.  **Prompt 结构变化**: 
    - 最终发送给 LLM 的 Prompt 中，Inner Monologue 部分不再是简单的 `[A]: ...` 列表，而是包含明确的“融合指令”。
    - 指令要求模型明确输出 `[Final Inner Thought]`。
2.  **日志验证**:
    - 在 `generate_response` 的日志或 Trace 中，能观察到模型输出了融合后的思维内容。
3.  **回复质量**:
    - 回复能体现出次要人格（Minor Persona）的微妙影响，而不仅仅是主要人格的单调输出。

## 4. 风险评估
- **模型遵循度**: 较弱的模型（如 gpt-3.5-turbo 或 7b 模型）可能忽略融合指令。
  - *缓解*: 使用清晰的分隔符和强制的 Output Format 指令。
- **Token 消耗**: 输出融合思维会增加少量的 Output Token 消耗。
  - *接受*: 相比增加一次完整的 HTTP Request 开销，这是可接受的。
