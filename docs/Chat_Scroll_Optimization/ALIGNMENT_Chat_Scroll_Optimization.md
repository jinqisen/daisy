# 任务对齐文档：聊天滚动条体验优化

## 1. 原始需求
用户反馈无法手动查看历史消息，因为每次有新消息（或组件更新）都会强制滚动到底部。
**核心需求**：
1. **智能滚动**：
   - 用户拉动滚动条查看历史时，保持位置，不自动滚动到底部。
   - 只有当滚动条处于底部（最新位置）时，收到新消息才自动滚动。
2. **新消息提示**：
   - 当用户在查看历史（未在底部）时收到新消息，显示"新消息"提示。
   - 点击提示可一键回到顶部（底部最新消息）。
3. **自身消息**：
   - 用户自己发送消息时，无论当前在哪里，强制滚动到底部。

## 2. 需求分析与理解
### 现有逻辑
- `ChatInterface.tsx` 中使用 `useEffect` 监听 `messages` 变化。
- 只要 `messages` 变化，立即调用 `scrollToBottom`。
- 没有任何检测当前滚动位置的逻辑。

### 改进方案
1. **引入滚动状态监测**：
   - 监听聊天容器的 `onScroll` 事件。
   - 维护 `isAtBottom` 状态（使用 `useRef` 避免频繁渲染，或结合 state）。
   - 判定标准：`scrollHeight - scrollTop - clientHeight < threshold` (e.g. 50px)。

2. **优化滚动触发条件**：
   - 在 `useEffect` [messages] 中：
     - 如果是**用户发送**的新消息（最后一条是 user）：强制滚动。
     - 如果是**AI回复**或**历史加载**：
       - 若 `isAtBottom` 为 true：自动滚动。
       - 若 `isAtBottom` 为 false：不滚动，显示"↓ 有新消息"悬浮按钮。

3. **交互细节**：
   - 点击"有新消息"按钮：调用 `scrollToBottom` 并隐藏按钮。
   - 用户手动滚动到底部：自动隐藏"有新消息"按钮。

## 3. 验收标准
- [ ] 用户向上滚动查看历史时，AI 生成回复不会导致页面跳动到底部。
- [ ] 用户查看历史时，若有新消息，出现悬浮提示。
- [ ] 点击悬浮提示，平滑滚动到底部。
- [ ] 用户处于底部时，AI 回复自动跟随滚动。
- [ ] 用户发送消息时，自动滚动到底部。
