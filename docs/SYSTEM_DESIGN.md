## 1. 引言与目标

**Daisy 是一个本地运行的 AI 情感陪伴桌面应用。** 用户与一个具备稳定人格、
长期记忆和主动性的角色对话;全部数据存在用户自己的机器上。

### 质量目标(按优先级)

| # | 目标 | 为什么排在这个位置 | 如何验证 |
|---|---|---|---|
| 1 | **对话不可中断** | 陪伴产品里"说不了话"等于产品死亡。曾因缺一把可选的搜索密钥导致整个对话任务崩溃、消息永久卡死 | 能力分级契约 + 12 节点降级测试 |
| 2 | **数据私有** | 对话内容是隐私。不存在服务端,不上传 | 关闭 mem0 遥测;密钥只存本地;可选本地锁 |
| 3 | **开箱即用** | 桌面用户不会配环境。曾需 Docker + Redis + Qdrant 五个进程 | 单进程零外部依赖;模型随包分发;离线可用 |
| 4 | **成本可控** | 用户自付 token | 执行预算账本;18/18 调用点记账 |
| 5 | **可演进** | 曾有 7 个循环依赖,"修一个坏一个" | 依赖方向护栏(棘轮机制) |

### 利益相关者

| 角色 | 关注点 |
|---|---|
| 终端用户 | 角色是否像个人、会不会打扰、数据是否安全 |
| 开发者 | 改动是否会从意外方向回弹 |
| 打包者 | 安装包能否离线开箱即用、是否泄漏密钥 |

## 2. 约束

| 类别 | 约束 | 影响 |
|---|---|---|
| 部署 | 单机桌面应用,无服务端 | 无法做"用户不在时"的推送;调度器只在应用打开时运行 |
| 分发 | keyless —— 安装包不得含任何 API Key | 首次运行必须引导用户填密钥 |
| 平台 | 已验证 macOS (Apple Silicon) | Windows 脚本存在但**未经验证** |
| 网络 | 中国大陆网络环境 | HuggingFace 不稳定 → 模型必须构建期拉取 |
| 成本 | 用户自付 LLM token | 需要预算上限与调用记账 |
| 数据库 | 无 Alembic | 用只做加列的轻量迁移 |

### 边界外(明确不做)

- 多用户 / 账号体系(那是 server 部署的语义,桌面版走免登录本地会话)
- 应用关闭时的主动推送(需系统级守护进程)
- 云端同步

## 4. 解决方案策略

| 问题 | 策略 | 关键权衡 |
|---|---|---|
| 五进程依赖太重 | Redis→进程内 fakeredis;Qdrant→本地路径;worker→并入后端 | 牺牲横向扩展换取零配置。桌面单用户无扩展需求 |
| 首次使用要下 1.3GB 模型 | 构建期拉取,随包分发 | .dmg 808M→941M,换取离线开箱即用 |
| 嵌入模型体积 | 选 bge-small(512 维)而非 bge-large(1024 维) | 召回质量略降,包体省 1.2GB |
| LLM 输出 JSON 不可靠 | 容错解析(标准解析失败再修复) | 实测**每次**角色卡生成都命中畸形 JSON |
| 一个功能挂掉整个对话 | 能力分级契约(essential/enhancement) | 增强节点失败自动降级,不靠作者记得写 try/except |
| 改一处从别处回弹 | 依赖方向护栏 + 棘轮基线 | 强制单向依赖,新增循环直接测试失败 |

### 5.1 容器视图

```
│  · 单实例锁 · 动态端口 · 退出时 SIGTERM→SIGKILL      │
│  ├── BrowserWindow ──► 前端 SPA(由后端同源托管)     │
│  └── spawn ──────────► 后端 sidecar(PyInstaller)    │
└─────────────────────────────────────────────────────┘
                              │
┌─────────────────────────────▼───────────────────────┐
│  后端 sidecar(单进程,FastAPI + uvicorn)            │
│  · 看门狗:父进程消失即 os._exit                     │
│  ├ HTTP API  ├ LangGraph 工作流  ├ APScheduler       │
│  ├ fakeredis(进程内)  ├ SQLite  ├ Qdrant(本地)    │
│  └ 本地模型:bge-small / MiniLM / goemotions         │
└─────────────────────────────────────────────────────┘
```

### 5.2 后端分层

严格单向依赖,**零循环**(由 `tests/test_module_boundaries.py` 强制):

| 层 | 包 | 职责 | 判断标准 |
|---|---|---|---|
| L0 | `core` | 基础设施 | 不含业务概念,换个产品也能用 |
| L1 | `agents` / `models` | 领域实体 / 持久化实体 | |
| L2 | `prompts` | 提示词渲染 | 消费领域实体,产出文本 |
| L3 | `services` / `multi_agent` | 用例 | 一个业务动作 |
| L4 | `workflow` / `tasks` | 编排 / 后台任务 | |
| L5 | `api` | 接口层 | |

实际依赖边(测试实时生成,全部向下):

```
agents      → core
models      → core
prompts     → agents, core
multi_agent → agents, core, models, prompts
services    → agents, core, models, multi_agent, prompts
tasks       → core, models, services, workflow
workflow    → core, models, prompts, services
api         → core, models, prompts, services, workflow
```

**依赖反转的两个手法**(底层需要上层能力时):
- 注册表 `core/job_registry.py` —— tasks 导入时自登记,core 只查表
- 可插拔接口 `core/trace_sink.py` —— core 持接口,services 注入实现

## 6. 运行时视图

### 6.1 对话主链路(DEEP 路由,实测 28–38 秒)

```
用户发消息 → POST /api/chat(立即返回 queued,消息落库 status=pending)
              │
              └─► chat_task(进程内异步)
                    │
                    route_logic ──► FAST / STANDARD / DEEP
                    │                (缓存 600s;线下见面意图强制 DEEP)
                    ▼ DEEP
                 analyze_emotion  [essential]  ~4s
                    │  中文→英译→GoEmotions 分类 + 投入度
                    ├──────┬──────┬──────┬──────┐
                    ▼      ▼      ▼      ▼      ▼      (并行)
              沟通风格  记忆检索  话题总结  画像  工具检查
              [enh]     [enh]    [enh]   [enh]  [enh]
                    │             ~10s                 ~5s
                    ├──────┬──────┘
                    ▼      ▼
               风格分析  角色思考(多人格并行 + 融合引擎)~18s
               [enh]     [enh]
                    └──────┬──────┘
                           ▼
                  generate_response [essential]
                    │  CO-STAR 提示词组装 + Reflexion 补丁回灌
                    ▼
                  save_memory_and_log [essential]
                    │  落库 + 状态快照 + 触发反思 + 后台写长期记忆
                    ▼
                  SSE 推送(多段发送,模拟真人打字节奏)
```

**能力分级**(`app/workflow/capability.py`):

| 等级 | 节点 | 失败行为 |
|---|---|---|
| essential | `analyze_emotion` `generate_response` `save_memory_and_log` `fast_generate` `standard_generate` | 向上传播,任务层统一处理 |
| enhancement | `retrieve_memory` `analyze_communication_style` `summarize_topic` `ensure_portrait` `analyze_style` `agent_thoughts` `tool_check` | **自动降级为兜底值,绝不中断对话** |

`fallback` 必须显式给出 —— 下游汇聚可能在等那个键,悄悄不写会让它一直等,
那是另一种形式的中断。

### 6.2 主动关心

```
APScheduler(每 15 分钟,进程内)
  → 枚举已知用户(读**数据库**)
  → 逐用户判定:
       忙碌保护(90 分钟内活跃过 → 跳过)
       静默时段(23:00–08:00 → 跳过)
       双轨门控:情感急救 / 常规陪伴(作息概率)
       配额(3/天)与冷却(4h)
  → Agent 决策是否开口 → 生成 → 落库(is_proactive=true)+ SSE
```

**固有限制**:调度器在后端进程内 —— **关掉应用就没有主动关心**。
它的定位是"你开着应用但没在看时的陪伴",不是"你不在时惦记你"。

### 6.3 首次运行

```
启动(28 秒,加载 torch/transformers)
  │  前端此时显示"正在启动本地服务",**不是**登录界面
  ▼
local_session → 200(未设本地锁)
  │
  ▼ configured=false
配置引导 → 填密钥 → **保存前探活** → 落库 + 热重载 provider
  │
  ▼
立即写入默认角色卡(解除门禁)→ 后台深度生成(150s 上限)→ 静默升级
```

## 8. 横切概念

### 8.1 配置

优先级:`.env` > `server_config.json` > Python 字段默认值。

> **踩过的坑**:换嵌入模型时只改了最低优先级的字段默认值,包里是 bge-small
> 而运行时找 bge-large,长期记忆直接报错。现有测试强制三处一致。

关键配置(实测生效值):

| 配置 | 值 | 说明 |
|---|---|---|
| `EMBEDDED_MODE` | true | 进程内 fakeredis + 本地 Qdrant |
| `EMBEDDING_MODEL_NAME` / `EMBEDDING_DIMS` | bge-small-zh-v1.5 / 512 | 两者必须一致,否则 Qdrant 静默拒写 |
| `EXEC_BUDGET_MAX_LLM_CALLS` / `MAX_TOKENS` | 25 / 40000 | 实测 DEEP 峰值 11 次 |
| `DEEP_TOOL_MAX_STEPS` | 3 | 工具循环上限 |
| `PROACTIVE_MAX_DAILY` / `COOLDOWN_HOURS` | 3 / 4.0 | |
| `PROACTIVE_BUSY_GUARD_MINUTES` | 90 | |
| `PROACTIVE_QUIET_*` | 23 → 8 | 硬性静默,正确处理跨午夜 |

### 8.2 存储

| 用途 | 技术 | 位置 |
|---|---|---|
| 结构化数据 | SQLite | 用户数据目录 |
| 向量 | Qdrant 嵌入模式 | 同上 |
| 缓存 / 队列 / 计数 | fakeredis(进程内) | 内存,**重启即失** |
| 记忆历史 | mem0 + SQLite | `MEM0_DIR` 重定向 |

> **重启即失是设计后果,不是 bug** —— 但凡"必须跨重启"的事实(用户名单、
> 最后活跃时间)都必须以数据库为准。主动关心曾因只读 Redis 而在重启后完全静默。

### 8.3 可观测性

| 埋点 | 落库 |
|---|---|
| 节点耗时 | `CHARACTER_PERFORMANCE` 日志 |
| 端到端延迟 | `SLO_E2E_LATENCY`(带 route) |
| LLM 调用轨迹 | `llm_traces` |
| 工作流轨迹 | `workflow_traces` |
| 反思评分 | `reflexion_logs` |
| RL 样本 | `rl_samples` |
| 主动消息 | `chat_history.is_proactive` |

### 8.4 安全与隐私

- 安装包**不含密钥**(打包时生成脱敏副本,测试强制)
- mem0 遥测(PostHog)已关闭
- 嵌入模式下 CORS 关闭(同源托管,开放等于让本机任意网页可调用)
- 本地锁:密码只存 hash,不上传、不可找回;**可选**,未设置时不拦人
- 桌面版禁用 register/login(404);server 部署禁用本地锁(404)

## 9. 架构决策记录

| # | 决策 | 理由 | 代价 |
|---|---|---|---|
| 1 | 去 Docker,单进程嵌入 | 桌面用户不会配环境 | 失去横向扩展(单用户无需) |
| 2 | fakeredis 替代 Redis | 零外部依赖 | 重启即失 → 关键事实必须落库 |
| 3 | 模型构建期拉取 | 运行时下载会卡住功能且断网即废 | 包体 +133 MB |
| 4 | bge-small 而非 large | 包体差 1.2 GB | 召回质量略降 |
| 5 | 免登录本地会话 + 365 天令牌 | 无服务端,短 TTL 无安全收益却会让长时间使用全部 401 | 令牌长期有效(仅本机) |
| 6 | 记忆 LLM 跟随对话 provider | 原硬编码 siliconflow,"规避风控"无证据支撑,代价是多一把密钥、没有就整个功能不可用 | 可能偶发风控拦截 |
| 7 | 能力分级契约 | 错误处理靠作者自觉迟早会漏 | 每个新节点必须声明等级 |
| 8 | 依赖护栏用棘轮而非一次性重构 | 避免大爆炸式替换 | 基线里每条都是待还的债 |
| 9 | 移除流式响应 | 与真人回复习惯不符 | 改用多段发送模拟打字节奏 |
| 10 | 主动关心参数偏保守 | 失败不对称:不够热情只是遗憾,**打扰不可逆** | 可能显得不够主动 |

| 质量属性 | 场景 | 实测 |

| 启动性能 | 打包版冷启动 | **28 秒**(源码 20 秒) |

| 成本 | 一次 DEEP 对话 | 11 次 LLM 调用(上限 25) |

## 11. 风险与技术债

| 风险 | 严重性 | 现状 |
|---|---|---|
| **Windows 未经验证** | 高 | 脚本存在但从未在 Windows 上跑过。**当前只应宣称支持 macOS** |
| 预算只有一个执行点 | 中 | 仅 ReAct 工具循环检查,而它在图中跑得早、累积调用少 → 正常对话几乎不触发。是病态循环的保险,不是逐节点闸门 |
| 主动关心只在应用打开时 | 中 | 固有限制;要做"不在时惦记"需系统级守护进程 |
| 情绪识别经中文→英翻译 | 中 | 置信度受损;已把 override 从"加频"改为"换语气"以降低误判代价 |
| 无 Alembic | 低 | 只做加列的轻量迁移;类型变更/删列需手工 |
| RL 仅采样未闭环 | 低 | 数据管线可用(context/action/reward),尚未用于在线决策 |
| `DAISY_CONFIG_PATH` 指向不存在文件时启动崩溃 | 低 | 桌面版首次运行会复制配置,当前无触发路径 |

### 已还清的债

7 个循环依赖全部消除;18/18 LLM 调用点已记账;3 个本地模型随包分发;
mem0 工作目录已迁出家目录;安装包已确认无密钥。
