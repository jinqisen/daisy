# 共识：优化 RAG 与 Agent 的交互流程

## 1. 核心变更点

### 1.1 系统提示词 (System Prompt) 重构
- **引入思维链 (Chain of Thought)**: 强制模型在生成回复前进行“内心独白”。
- **强化记忆转化指令**: 明确告知模型 RAG 提供的 `context` 是“潜意识/外部资料”，禁止直接朗读，必须经过“消化”和“转述”。
- **增加输出控制**: 
    - 方案：要求模型输出 `<thought>...</thought>` 标签包裹思考过程。
    - 后处理：后端代码负责在流式输出或最终保存时过滤掉 `<thought>` 部分（或者保留在 metadata 中供调试，前端只展示回复）。

### 1.2 后端逻辑变更 (`src/api/chat.py`)
- **`_build_immersive_system_prompt`**: 更新 Prompt 模板，加入 CoT 指令和 RAG 使用规范。
- **`event_generator` (流式响应)**: 增加逻辑以处理 `<thought>` 标签。
    - *选项 1*: 实时流式传输所有内容，前端隐藏 `<thought>`。
    - *选项 2*: 后端缓冲，检测到 `<thought>` 结束才开始推流（会有首字延迟）。
    - *选项 3*: 后端实时流式传输，但通过特殊标记告诉前端这是“思考”，前端选择性展示。
    - *决策*: 为了最快见效且不改前端，采用 **后端实时过滤**。
        - 简单起见，如果 CoT 放在最前面，我们可以先缓冲直到 `</thought>` 出现，或者只在 `add_message` 保存时过滤，流式传输时包含它（用户能看到思考过程也是一种“智能”的体现，或者用户确实不想看）。
        - *修正*: 用户反馈的是“直接回答不对”，暗示想要更拟人的结果。如果能看到 AI 在“思考：根据家族记载...”，体验可能更好，也可能破坏沉浸感。
        - *最终策略*: **隐藏思考过程**。后端流式传输时，使用一个简单的状态机或 Buffer 来拦截 `<thought>...</thought>` 内容，不发给前端。

## 2. 详细设计

### 2.1 Prompt 模板更新
```python
overlay = f"""
...
【交互策略】
1. **获取信息**: 从【潜意识记忆】中提取相关事实。
2. **沉浸式思考**: 
   - 作为一个生活在那个世界的人，你如何看待这个问题？
   - 你的性格（{personality_keywords}）如何影响你的回答？
3. **生成回复**: 使用你的口吻（{style_keywords}）回答。

【输出格式】
请严格按照以下格式输出：
<thought>
在此处进行你的思考分析...
</thought>
(此处直接开始你的回复内容)
"""
```

### 2.2 流式过滤器设计 (`StreamRedactor` 扩展)
扩展 `_StreamRedactor` 或新增 `_ThoughtFilter`。
- 维护一个状态 `in_thought`。
- 遇到 `<thought>` 进入状态，缓冲不输出。
- 遇到 `</thought>` 退出状态，清空缓冲。
- 正常文本直接 yield。

## 3. 验收标准
- 用户提问后，AI 回复的内容完全符合人设，无机械感。
- 无论是流式响应还是最终历史记录，都不包含 `<thought>` 标签内容。
- 响应速度在可接受范围内（CoT 会增加 token 消耗，但值得）。

## 4. 确认无歧义
- 用户要求的“塞到AI智能体”即通过 Prompt Context 注入。
- “符合人物档案”即通过 System Prompt 约束。
