# 共识文档：每次响应客户对话的大模型调用分析

## 1. 需求描述与验收标准

**需求**: 检查并分析每次响应客户对话时，系统进行了哪些大模型 (LLM) 调用。

**验收标准**:
- [x] 识别出所有可能的 LLM 调用点。
- [x] 分析每个调用点的触发条件 (是否缓存、是否条件触发)。
- [x] 统计最小、典型和最大调用次数。
- [x] 输出清晰的分析报告。

## 2. 分析总结

经过代码审查，确认系统在一次标准对话流程中涉及 **3 到 11 次** LLM 调用。

### 核心调用点
1.  **预处理**: 情感翻译 (仅中文)、记忆检索查询优化 (仅长文)。
2.  **决策与上下文**: 策略选择、话题总结、风格分析 (均有 Redis 缓存)。
3.  **生成核心**: 
    - **CrewAI 内心独白**: 1-3 次 (取决于活跃人格数量)。
    - **Prompt 工程**: 1 次 (CO-STAR 指令组装)。
    - **最终生成**: 1 次。

### 调用量级
- **最小**: 3 次 (全缓存命中、简单输入、单一人格)。
- **典型**: 7-8 次。
- **最大**: 11 次 (冷启动、复杂输入、多人格)。

## 3. 下一步建议 (可选)

如果需要降低 Token 消耗或延迟，建议关注以下优化点：
1.  **缓存策略**: 延长 `Strategy`, `Style`, `Topic` 的 Redis 缓存时间。
2.  **合并调用**: 考虑将 `CO-STAR` 指令生成直接嵌入最终生成的 System Prompt 中 (减少 1 次调用)。
3.  **CrewAI 优化**: 限制最大活跃人格数量为 1 或 2，或仅在特定情感强度下触发内心独白。
